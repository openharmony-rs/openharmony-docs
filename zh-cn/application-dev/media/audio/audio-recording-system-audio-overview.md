录制系统音频通常称为内录，是指设备以系统内部播放音频作为采集源进行录制。与通过麦克风采集设备周围声音的外录不同，内录直接获取设备内部应用播放的音频数据，不受周围环境噪声影响。

## 适用场景

内录适用于以下需要获取设备内部播放音频的场景：

- 会议共享：将设备中播放的演示音频、视频声音等内容共享给参会者。
- 直播推流：将游戏、视频等应用播放的音频数据接入直播编码和推流链路。
- 音频录制：录制设备内部播放的音频，用于保存或后续编辑。
- 音频分析：获取内部播放音频的PCM数据，用于听歌识曲等音频分析业务。

## 内录与外录的区别

| 特性 | 内录（系统音频录制） | 外录（麦克风录制） |
|------|---------------------|-------------------|
| 采集内容 | 设备内部播放的音频，不采集周围环境声音 | 麦克风接收到的声音，可能包含周围环境声音 |
| 录制质量 | 不受周围环境噪声影响 | 可能受到周围环境噪声影响 |
| 适用场景 | 直播推流、在线会议、音频录制、音频分析 | 录音机、相机录像、语音通话、语音识别 |

## 实现与授权

内录由系统从设备内部正在播放的音频中获取数据，并将音频数据提供给发起内录的应用。该过程不会通过麦克风采集周围环境声音。

由于系统音频可能包含媒体内容、消息提示或其他应用播放的信息，应用请求启动内录时，系统会进行用户授权检查，以确保用户知情。不同设备形态的授权弹框表现可能存在差异，应用应以启动接口异步回调返回的状态作为授权和启动结果。

## 播放端隐私保护

播放端还可以控制自身音频是否允许被其他应用录制。标记为隐私保护的播放流不会被内录采集，从而避免敏感音频在未经播放端允许的情况下被录制。具体配置方法请参考[配置目标播放流的内录策略](implement-system-audio-recording.md#配置目标播放流的内录策略)。

## 如何选择内录接口

从API version 26.0.0开始，三方应用可以通过ArkTS AudioCapturer或C API OH_AudioCapturer录制系统音频。根据使用场景，开发者也可以选择AVScreenCapture录屏接口。

| 接口类型 | 三方开放版本 | 适用场景 | 开发指导 |
| -------- | ------------ | -------- | -------- |
| ArkTS AudioCapturer或C API OH_AudioCapturer | API version 26.0.0 | 仅需要录制系统音频，或需要将PCM数据接入自定义编码、算法和传输链路，例如直播推流、在线会议、听歌识曲和音频分析。 | [实现录制系统音频(ArkTS/C/C++)](implement-system-audio-recording.md) |
| AVScreenCapture录屏接口 | API version 10 | 需要同时录制屏幕视频和系统音频，例如屏幕录制、制作教学视频和游戏录像。 | [AVScreenCapture录屏基础流程](../media/avscreencapture-c-basic-process.md) |
