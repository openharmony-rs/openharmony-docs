# OHAudio

## 概述

提供音频模块C接口定义，可用于实现音频播放、录制和相关的音量、设备、会话管理等功能， 服务于媒体播放、语音通话、游戏音频等音频业务开发场景。

**系统能力：** SystemCapability.Multimedia.Audio.Core

**起始版本：** 10

## 文件汇总

| 名称 | 描述 |
| -- | -- |
| [native_audiorenderer.h](capi-native-audiorenderer-h.md) | OH_AudioRenderer提供音频播放流功能，目前主要用于播放PCM（Pulse Code Modulation）音频数据。在播放过程中， 需要持续向系统传递待播放的音频数据，适用于需要在播放前对音频数据进行预处理、 对播放过程有更灵活控制要求的场景，如专业媒体播放、游戏、语音通话等。 不同播放场景需通过[OH_AudioStream_Usage](capi-native-audiostream-base-h.md#oh_audiostream_usage)配置合适的播放流类型，以便让系统匹配合适的音效、音量、设备与焦点策略。 <br>使用OH_AudioRenderer实现音频播放功能时，需先设置音频核心参数（采样率、声道、编码类型、采样格式、使用场景等） 并设置数据写入回调，通过 [OH_AudioStreamBuilder_GenerateRenderer](capi-native-audiostreambuilder-h.md#oh_audiostreambuilder_generaterenderer)创建播放流实例，随后调用[OH_AudioRenderer_Start](capi-native-audiorenderer-h.md#oh_audiorenderer_start)开始播放。 播放过程中可通过 [OH_AudioRenderer_Pause](capi-native-audiorenderer-h.md#oh_audiorenderer_pause)控制播放暂停、[OH_AudioRenderer_Stop](capi-native-audiorenderer-h.md#oh_audiorenderer_stop)控制播放停止， 退出播放时通过[OH_AudioRenderer_Release](capi-native-audiorenderer-h.md#oh_audiorenderer_release)释放资源。 OH_AudioRenderer内具备状态机，仅在特定状态下调用相应方法才能正常工作。 <br>由于系统对音频流数量有限制，不再使用时应及时调用[OH_AudioRenderer_Release](capi-native-audiorenderer-h.md#oh_audiorenderer_release)释放资源， 避免后续创建音频流失败。 |
| [native_audio_device_base.h](capi-native-audio-device-base-h.md) | 本文件提供音频设备管理模块所依赖的基础枚举和结构体定义， 包括音频设备类型、音频设备描述结构体以及从设备描述结构体查询具体设备参数的接口。 <br>该模块为音频设备管理提供基础数据结构和查询能力， 支持获取音频设备的角色、类型、ID、名称、地址、采样率、声道数、编码类型等信息， 适用于需要查询和管理音频设备属性的场景。 |
| [native_audio_common.h](capi-native-audio-common-h.md) | 声明音频公共基础枚举定义， 包括音频错误码、音频场景、铃声模式、录音降噪模式等，在音频播放、音频录制、音频管理相关接口中使用。 |
| [native_audiostreambuilder.h](capi-native-audiostreambuilder-h.md) | 本文件提供音频播放和录制流构造器接口。 <br>为便于扩展，音频系统采用建造者设计模式实现音频播放和录制流对象的构造。 <br>开发者必须设置音频流的核心参数，包括采样率、声道数或声道掩码、采样格式、编码类型和使用场景， 其他参数开发者可以按需设置。 <br>对于回调函数，播放和写入数据和录制和读取数据回调必须设置，因为这是应用与系统传递数据的唯一方式。 <br>在设置完所需的参数和回调函数后，调用[OH_AudioStreamBuilder_GenerateRenderer](capi-native-audiostreambuilder-h.md#oh_audiostreambuilder_generaterenderer) 或 [OH_AudioStreamBuilder_GenerateCapturer](capi-native-audiostreambuilder-h.md#oh_audiostreambuilder_generatecapturer)即可完成播放流或录制流的构造。 在这一步骤，所有设置项才会真正被用于音频流配置，相关的参数支持范围和权限要求也会在此时进行校验。 |
| [native_audio_session_base.h](capi-native-audio-session-base-h.md) | 声明音频会话模块使用的基础数据结构和枚举定义。 |
| [native_audio_accessory_common.h](capi-native-audio-accessory-common-h.md) | 声明外部音频配件设备接口的公共数据结构。<br> 定义音频配件接口的公共类型。 |
| [native_audiostream_base.h](capi-native-audiostream-base-h.md) | 声明音频播放和录制流模块使用的基础数据结构和枚举定义。 |
| [native_audiocapturer.h](capi-native-audiocapturer-h.md) | OH_AudioCapturer提供音频录制流功能，目前主要用于录制PCM（Pulse Code Modulation）音频数据。在录制过程中， 需要持续从系统读取已录到的音频数据，适用于需要在录制后对音频数据进行后处理、 对录制过程有更灵活控制要求的场景，如专业媒体录制、语音识别、语音消息、语音通话等。 不同录制场景需通过[OH_AudioStream_SourceType](capi-native-audiostream-base-h.md#oh_audiostream_sourcetype)配置合适的录音源类型，以便让系统匹配合适的音效、设备与焦点策略。 <br>使用OH_AudioCapturer实现音频录制功能时，需先设置音频核心参数（采样率、声道、编码类型、采样格式、使用场景等） 并设置数据读取回调，通过 [OH_AudioStreamBuilder_GenerateCapturer](capi-native-audiostreambuilder-h.md#oh_audiostreambuilder_generatecapturer)创建录制流实例，随后调用[OH_AudioCapturer_Start](capi-native-audiocapturer-h.md#oh_audiocapturer_start)开始录制。 录制过程中可通过 [OH_AudioCapturer_Pause](capi-native-audiocapturer-h.md#oh_audiocapturer_pause)控制录制暂停、[OH_AudioCapturer_Stop](capi-native-audiocapturer-h.md#oh_audiocapturer_stop)控制录制停止， 退出录制时通过[OH_AudioCapturer_Release](capi-native-audiocapturer-h.md#oh_audiocapturer_release)释放资源。 OH_AudioCapturer内具备状态机，仅在特定状态下调用相应方法才能正常工作。 <br>使用麦克风录制时，需申请ohos.permission.MICROPHONE权限，并且录制流只能在前台启动，启动后可退至后台保持运行。 <br>由于系统对音频流数量有限制，不再使用时应及时调用[OH_AudioCapturer_Release](capi-native-audiocapturer-h.md#oh_audiocapturer_release)释放资源， 避免后续创建音频流失败。 |
| [native_audio_manager.h](capi-native-audio-manager-h.md) | 本文件提供音频基础管理功能的接口。 <br>当前支持音频场景信息的查询以及音频场景变化的监听。 |
| [native_audio_accessory_manager.h](capi-native-audio-accessory-manager-h.md) | 声明音频配件管理相关的接口。<br> 该文件接口用于管理音频配件的创建、连接、断开和销毁等功能。 |
| [native_audio_session_manager.h](capi-native-audio-session-manager-h.md) | 本文件提供音频会话管理功能的接口。 <br>在介绍音频会话能力前，需要先了解如下概念： <br>音频焦点：系统用于管理多个音频竞争的机制，决定了音频播放的优先级，高优先级的音频可以中断或压低低优先级的音频。 <br>音频会话：表示应用的音频业务，开发者可以通过音频会话管理应用内所有音频的焦点和设备选择策略。 音频会话的配置会影响应用内的所有音频流。<br> <br>音频会话的主要使用场景： <br>a) 系统默认的焦点策略不能满足开发者要求，可使用音频会话修改策略。 <br>b) 应用音频业务流程涉及切换不同音频流（如短视频切换），要保证切换过程中焦点不丢失，可使用场景级音频会话。 此类会话激活过程中，焦点不会随音频流停止而丢失。 <br>c) 设置应用当前音频业务的播放输出设备或录音输入设备偏好。<br> <br>音频会话有两种使用模式： <br>a) 音频流级会话：不使用[OH_AudioSessionManager_SetScene](capi-native-audio-session-manager-h.md#oh_audiosessionmanager_setscene)接口设置场景时，音频系统会按会话维度管理音频流， 但音频业务的生命周期还是与音频流状态绑定。因此焦点的请求和释放， 仍是跟随音频流的启动和停止。 <br>b) 场景级会话：使用[OH_AudioSessionManager_SetScene](capi-native-audio-session-manager-h.md#oh_audiosessionmanager_setscene)接口设置场景后， 音频系统会将音频业务的生命周期与音频会话状态绑定，焦点的请求和释放，会跟随音频会话的激活和停止。 <br>推荐开发者优先选择场景级音频会话，以便更灵活的控制业务生效的时机。 <br>本文件提供的接口，支持的主要功能包括配置音频会话，激活/停用音频会话、监听音频会话停用事件、 设置应用输入设备偏好等。 |
| [native_audio_volume_manager.h](capi-native-audio-volume-manager-h.md) | 本文件提供音频音量管理功能的接口。 <br>在介绍音量管理能力前，需要先了解如下概念： <br>音量类型：系统将不同场景的音频播放流按[OH_AudioStream_Usage](capi-native-audiostream-base-h.md#oh_audiostream_usage)划分。由于OH_AudioStream_Usage种类很多， 为便于管理音量，系统将其进行分组， 每组OH_AudioStream_Usage对应一种音量类型，例如AUDIOSTREAM_USAGE_MUSIC和AUDIOSTREAM_USAGE_MOVIE都对应媒体音量， 当一种类型的音量改变， 此类型对应的所有音频播放流音量都会受到影响。 <br>音量等级：系统是以音量等级为单位进行音量大小调节的，实际的音量增益会基于音量等级计算得出， 确保调节时音量听感变化均匀。 不同的音量类型，可设置的音量等级范围可以是不同的。 <br>铃声模式：系统内用于控制铃声和通知音行为的状态，分为响铃、振动、静音三种模式，通常在具备通话能力的设备中使用。 铃声模式与铃声类型的音量存在联动关系。 <br>本文件提供的接口，支持开发者查询指定OH_AudioStream_Usage下的最大、最小音量等级， 以及当前系统设置的音量等级和静音状态，支持监听系统音量变化，也支持查询和监听系统当前铃声模式信息。 <br>由于系统不希望在没有用户感知的情况下发生音量变化，本文件不提供直接设置系统音量的接口。 如果开发者需要实现调节系统音量的功能，推荐使用AVVolumePanel。 <br>当前系统并未提供录音音量的管理功能，如果开发者需要调整录音音量，可在获取录音原始数据后自行调整数据增益。 |
| [native_audio_stream_manager.h](capi-native-audio-stream-manager-h.md) | 本文件提供音频流管理功能的接口。 <br>音频流是对系统内音频播放和录制流的统称。音频系统会根据音频流的配置，如播放流的[OH_AudioStream_Usage](capi-native-audiostream-base-h.md#oh_audiostream_usage) 和录制流的[OH_AudioStream_SourceType](capi-native-audiostream-base-h.md#oh_audiostream_sourcetype)， 为音频流选择合适的音频通路，以达到最佳的音频体验。 <br>在不同设备上，通路支持的情况存在差异，本模块提供了能力查询接口， 开发者可传入待播放或录制音频流的基础属性和用途进行查询。 |
| [native_audio_accessory_input_stream_manager.h](capi-native-audio-accessory-input-stream-manager-h.md) | 声明音频配件输入流管理器相关接口。<br> 该文件接口用于管理音频配件的输入音频流，包括回调注册、数据写入和缓冲区查询等功能。 |
| [native_audio_resource_manager.h](capi-native-audio-resource-manager-h.md) | 本文件提供音频资源管理功能的接口。 <br>音频播放或录制都需要持续对音频数据进行处理，消耗系统CPU资源。 当处理性能不足时，会出现杂音或卡顿问题，因此系统提供资源管理接口帮助应用开发者优化音频处理线程的性能。 <br>音频资源管理主要通过音频工作组实现。音频工作组是一组音频数据处理线程集合， 开发者通过接口将应用内音频数据处理相关线程添加到音频工作组，合理设置数据处理的预期完成时间，系统会平衡功耗和性能， 按照工作组内线程负载分配不同CPU资源，保障数据按时处理完成。 <br>音频工作组必须配合音频播放业务使用，支持的音频场景包括音乐、视频、听书、导航和语音通话。 没有音频流播放时，系统不会对线程性能进行优化。 <br>音频工作组的使用数量也存在约束，每个应用进程最多创建2个工作组，且进程内所有工作组总共最多添加4个处理线程。 |
| [native_audio_debugging_manager.h](capi-native-audio-debugging-manager-h.md) | 本文件提供适用于音频调试场景使用的接口。 <br>针对音频开发的特点和常见问题，系统将开发者调试音频功能所需要的系统内部信息通过接口提供出去， 便于开发者查看应用内音频业务对象的状态，用于定位用户音频功能问题。 <br>使用调试接口首先需要通过[OH_AudioManager_GetAudioDebuggingManager](capi-native-audio-debugging-manager-h.md#oh_audiomanager_getaudiodebuggingmanager) 获取音频调试管理器实例，通过该对象调用其他音频调试接口，包括应用快照、音频播放快照、音频录制快照等。 |
| [native_audio_device_enhance_manager.h](capi-native-audio-device-enhance-manager-h.md) | 本文件提供音频设备管理增强功能的接口。 <br>相比通用的音频设备管理接口文件仅提供查询设备状态的能力， 本文件提供的接口可支持按应用或按音频流切换输入和输出设备。 适用于需要在应用内实现应用级或流级音频设备切换的场景，例如多音频应用同时运行时的设备管理、 专业音频应用需要指定特定设备、或者用户需要在应用内自定义音频设备选择等场景。 通过精细化控制音频路由，可以提升应用的音频管理灵活性和用户体验。 <br>但这种能力对系统音频底层架构存在依赖，并非所有设备都能支持，因此在使用前建议先调用能力查询接口进行查询。 |
| [native_audio_routing_manager.h](capi-native-audio-routing-manager-h.md) | 本文件提供音频路由管理功能的接口。 <br>音频系统会为每个音频流选择默认的输入输出设备。对于音频播放流，系统会根据播放流的[OH_AudioStream_Usage](capi-native-audiostream-base-h.md#oh_audiostream_usage)， 在可用的输出设备中选择； 对于音频录制流，系统会根据录制流的 [OH_AudioStream_SourceType](capi-native-audiostream-base-h.md#oh_audiostream_sourcetype)，在可用的输入设备中选择。 <br>本文件提供的接口，支持开发者查询在线设备，监听设备在线状态变化，查询首选输入或输出设备，监听首选设备变化， 查询麦克风堵塞状态等。 当前并不提供主动选择设备的能力。 |
