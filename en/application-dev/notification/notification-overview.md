Notification Kit ([user notification service](notification-glossary.md#notification-kit)) provides a publishing channel for [local notifications](notification-glossary.md#local-notification). With Notification Kit, you can push notifications generated by your application directly to users on the client. Depending on the notification type and publishing scenario, a local notification produces the corresponding ringtone, vibration, banner, lock screen display, automatic screen-on, status bar icon, and display in the [notification center](notification-glossary.md#notification-center).

## When to Use

When an application is running, you can use Notification Kit to publish notifications to users.<!--RP1--><!--RP1End-->

You can use the [local notification](notification-glossary.md#local-notification) capability in various scenarios, such as synchronizing upload and download progress, publishing instant customer service and payment notifications, and updating step counts.

## Capability Scope

Notification Kit supports the following capabilities:

 - Publishes notifications in the form of text or progress bar.

 - Carries or updates the application notification badge.

 - Cancels one or all published notifications.

 - Queries the list of published notifications.

 - Queries the status of the notification function of an application.

 - Enables notification publishing (disabled by default) by triggering an authorization dialog to request user consent for sending notifications.

## Service Flow

 ![notification_principle](figures/notification_principle.png) 

The main service flow of using Notification Kit is as follows:

1.Request [notification authorization](notification-glossary.md#notification-authorization).

2. Publish a notification to Notification Kit.

3.Display the notification in the [notification center](notification-glossary.md#notification-center).

## Constraints

- The number of published notifications from a single application that can be retained in system entries such as the [notification center](notification-glossary.md#notification-center) is limited (currently up to 24).

- The notification cannot exceed 200 KB (due to cross-process serialization).

- The publication and update frequencies for notifications must meet the following requirements. Otherwise, the publication or update fails and the corresponding error code is returned.

  - The total number of notifications published by an application cannot exceed 10 per second, and that of notifications updated cannot exceed 20 per second.

  - The total number of notifications published by all third-party applications cannot exceed 15 per second, and that of notifications updated cannot exceed 30 per second.

  <!--Del-->

  - The total number of notifications published by all system applications cannot exceed 15 per second, and that of notifications updated cannot exceed 30 per second.

## Relationship with Related Kits

- Notifications created by Notification Kit are displayed immediately in system entries such as the [notification center](notification-glossary.md#notification-center). If you want scheduled notifications that still remind users after the application moves to the background or its process is terminated, such as flash-sale reminders in shopping applications, you can create them through [`Background Tasks Kit`](../task-management/background-task-overview.md). Currently, notification reminder features based on countdown, calendar, and alarm types are supported.

- You can use the [getWantAgent](../reference/apis-ability-kit/js-apis-app-ability-wantAgent.md#wantagentgetwantagent) API of [Ability Kit](../application-models/abilitykit-overview.md) to set the **WantAgent** triggered when a user taps a notification.<!--RP2-->
