## Overview

Starting from API version 26.0.0, HarmonyOS supports intelligent smooth high-speed playback decoding. This capability combines hardware decoding with a human visual perception model to optimize decoding performance at the system level.

In conventional media pipelines, increasing the playback speed proportionally increases the theoretical frame rate that must be processed. For example, playing a 60 fps video at 3.0× requires processing up to 180 frames per second, which introduces the following challenges:
1. On mobile devices, the display frame rate is typically limited by the system's power management policy (commonly 60 fps), which is much lower than the theoretical frame rate required for high-speed playback. During high-speed playback, the human visual system becomes less sensitive to subtle motion because of persistence of vision and reduced motion sensitivity. Decoding and rendering these visually insignificant frames consumes computing resources without noticeably improving the viewing experience.
2. In conventional media pipelines, frame dropping for high-speed playback is typically performed at the rendering stage in the application layer. By that point, the unnecessary frames have already been processed by the decoder. Although applications can perform content-aware frame selection before decoding, doing so generally requires computationally intensive pixel-level analysis, such as optical flow estimation, which increases overall power consumption.

Intelligent smooth high-speed playback decoding eliminates the need for complex pixel-level image analysis. Instead, it leverages motion vectors (MVs) generated by the hardware decoder together with the temporal scalability information in the video bitstream to dynamically adjust the frame retention strategy based on playback speed. This approach reduces decoding and rendering workloads, effectively controls device temperature, and delivers a smoother playback experience than conventional uniform frame dropping.

## Frame Retention Modes

The decoder provides the following frame retention modes. Select the appropriate mode based on your playback scenario.

| Mode | Working Principle | Application Scenario |
| :--- | :--- | :--- |
| **Adaptive (ADAPTIVE)** | Dynamically adjusts the frame retention strategy based on the current playback speed. The system dynamically analyzes video motion characteristics based on the current playback speed passed by the application, and preferentially drops non-key frames with lower visual perception weight. | Recommended for high-speed playback scenarios, providing a smoother experience that better aligns with human visual continuity than uniform frame dropping without content differentiation. |
| **Full passthrough (FULL)** | Decodes and outputs all input frames without frame dropping. | Applies to non-multiplied-speed or slow playback scenarios. |
| **Uniform (UNIFORM)** | Uniformly retains frames according to a developer-specified ratio. | Suitable for specialized workload reduction and performance optimization scenarios, such as thermal mitigation under high device temperatures or improving timeline scrubbing smoothness during video editing previews. |

## Parameter Description

This capability takes effect only after you actively deliver the configuration. Configure the following key-value pairs in [OH_AVFormat](../../reference/apis-avcodec-kit/capi-core-oh-avformat.md) to precisely control the behavior.

1. **OH_MD_KEY_VIDEO_DECODER_FRAME_RETENTION_MODE (retention mode)**
   - Type: `int32_t`
   - Value range: See [OH_FrameRetentionMode](../../reference/apis-avcodec-kit/capi-native-avcodec-base-h.md#oh_frameretentionmode).
   - Description: Serves as the master switch and mode selector of the capability. It can be configured during the initialization phase through [OH_VideoDecoder_Configure()](../../reference/apis-avcodec-kit/capi-native-avcodec-videodecoder-h.md#oh_videodecoder_configure), or switched at runtime through [OH_VideoDecoder_SetParameter()](../../reference/apis-avcodec-kit/capi-native-avcodec-videodecoder-h.md#oh_videodecoder_setparameter). When playback starts at normal speed, you are advised to initialize it to FULL mode.

2. **OH_MD_KEY_VIDEO_DECODER_SPEED**
   - Type: `double`
   - Value range: Greater than `0.0`.
   - Description: When configuring or switching to Perceptual Adaptive mode, you are advised to explicitly configure the current playback speed at the same time to achieve optimal algorithm accuracy. Update it synchronously when the speed changes. No configuration is required when initializing to FULL mode.

3. **OH_MD_KEY_VIDEO_DECODER_FRAME_RETENTION_RATIO (retention ratio)**
   - Type: `double`
   - Value range: `[0.01, 1.0]` (for example, `0.5` means retaining 50% of decoded frames).
   - Description: Takes effect only in UNIFORM mode. When the configured value is out of range or abnormal, the system falls back to a target frame rate of 30 fps by default.

## Constraints

- **Supported formats**: This capability is available only for video decoding and currently supports H.264, H.265, and H.266 video streams.
- **Invalid parameter handling**: In UNIFORM mode, if the configured retention ratio is invalid or not explicitly specified, the system defaults to a target output frame rate of 30 fps for decoding and display.
- **Hardware capability fallback**: Perceptual Adaptive mode relies on the hardware decoder's ability to output motion vector (MV) information. On hardware platforms where MV data cannot be provided, the system automatically triggers a basic fallback strategy at the underlying layer (while still retaining the Perceptual Adaptive mode state externally). In this case, the system can still maintain basic smooth playback, but cannot obtain the optimal benefits based on content awareness.
- **MV information output**: Perceptual Adaptive mode relies on the MV information output during decoding. The specific configuration requirements vary with the system version.
  - On devices running <!--RP1-->OpenHarmony 7.0.0.109 or later<!--RP1End-->, MV information can be obtained after switching to Perceptual Adaptive mode at runtime, regardless of the frame retention mode configured during initialization. Whether MV information is available still depends on the hardware decoder's support capability.
  - On system versions that support this capability but are earlier than <!--RP2-->OpenHarmony 7.0.0.109<!--RP2End-->, Perceptual Adaptive mode must be configured during the initialization phase to obtain MV information. If another mode is configured during initialization, MV information cannot be obtained after switching to Perceptual Adaptive mode at runtime, and the frame dropping strategy degrades to dropping frames at fixed intervals (when the decoding frame rate is greater than or equal to 45 fps, the target output frame rate is 45 fps; otherwise, no frames are dropped), reducing the benefits of Perceptual Adaptive mode.
- **Audio-video synchronization**: The frame retention mechanism determines only which frames are retained. It preserves the original presentation timestamp (PTS) and decoding timestamp (DTS) of retained frames and therefore does not affect audio-video synchronization.

## High-Speed Playback Development

For conventional video playback services, a strategy that combines initialization-stage configuration with dynamic switching is recommended.

- **Initialization**: When playback starts at normal speed, configure FULL mode before video playback starts. There is no need to set the decoding speed parameter.
- **Dynamic switching**: During playback, when the target speed is greater than 1.0x, deliver Perceptual Adaptive mode and the current speed in the same OH_AVFormat through OH_VideoDecoder_SetParameter(). When the speed returns to 1.0x or lower, switch back to FULL mode to restore full-frame decoding output.

### Initialization Stage Configuration

The following example starts playback at normal speed and configures the Full Passthrough mode. After completing the synchronous mode configuration, `SetOptionalFormatFeatures` calls `ConfigureSmartFluency(format)` and checks the return value when `sampleInfo.codec.isSmartFluencySupported` is `true`. Then `VideoDecoder::Configure` calls `OH_VideoDecoder_Configure()` to complete the configuration. This helper function only sets the parameters of this capability and does not create or destroy the `OH_AVFormat`.

If your service starts playback directly at a high speed, you can also configure the Perceptual Adaptive mode during initialization. In this case, it is recommended to explicitly set `OH_MD_KEY_VIDEO_DECODER_SPEED` to the actual startup speed.

<!-- @[configure_full_baseline](https://gitcode.com/openharmony/applications_app_samples/blob/master/code/BasicFeature/Media/AVCodec/entry/src/main/cpp/capabilities/video_decoder.cpp) -->

``` C++
bool ConfigureSmartFluency(OH_AVFormat *format)
{
    bool ret = OH_AVFormat_SetIntValue(format, OH_MD_KEY_VIDEO_DECODER_FRAME_RETENTION_MODE,
        OH_FRAME_RETENTION_MODE_FULL);
    CHECK_AND_RETURN_RET_LOG(ret, false, "Set smart fluency initial mode failed");
    return true;
}
```

### Switching Frame Retention Modes Dynamically

The system supports dynamic switching of the frame retention mode at runtime. You can call `OH_VideoDecoder_SetParameter()` to apply the configuration in real time. The timing at which the parameter takes effect follows the standard behavior of this API.

<!-- @[onUserSpeedChanged](https://gitcode.com/openharmony/applications_app_samples/blob/master/code/BasicFeature/Media/AVCodec/entry/src/main/cpp/capabilities/video_decoder.cpp) -->

``` C++
int32_t VideoDecoder::OnUserSpeedChanged(double targetSpeed)
{
    OH_AVFormat *param = OH_AVFormat_Create();
    CHECK_AND_RETURN_RET_LOG(param != nullptr, AVCODEC_SAMPLE_ERR_ERROR, "AVFormat create failed");

    // Introduce epsilon to handle precision comparison for the double type.
    const double EPSILON = 1e-6;

    const bool enableAdaptive = targetSpeed > 1.0 + EPSILON;
    if (enableAdaptive) {
        // Scenario: High-speed playback (e.g., 1.5x, 2.0x, 3.0x).
        // Strategy: Enable the adaptive mode.
        OH_AVFormat_SetIntValue(param, OH_MD_KEY_VIDEO_DECODER_FRAME_RETENTION_MODE,
                                OH_FRAME_RETENTION_MODE_ADAPTIVE);
        OH_AVFormat_SetDoubleValue(param, OH_MD_KEY_VIDEO_DECODER_SPEED, targetSpeed);
    } else {
        // Scenario: Normal playback (1.0x) or slow playback (<1.0x).
        // Strategy: Switch to the full mode to ensure every frame is sent for display.
        OH_AVFormat_SetIntValue(param, OH_MD_KEY_VIDEO_DECODER_FRAME_RETENTION_MODE,
                                OH_FRAME_RETENTION_MODE_FULL);
    }

    // Deliver parameters in real time to dynamically adjust the system frame retention strategy.
    int32_t ret = OH_VideoDecoder_SetParameter(decoder_, param);
    OH_AVFormat_Destroy(param);
    CHECK_AND_RETURN_RET_LOG(ret == AV_ERR_OK, AVCODEC_SAMPLE_ERR_ERROR,
                             "SetParameter failed, ret: %{public}d", ret);
    if (enableAdaptive) {
        AVCODEC_SAMPLE_LOGI("Smart fluency mode changed to ADAPTIVE, speed: %{public}.2f", targetSpeed);
    } else {
        AVCODEC_SAMPLE_LOGI("Smart fluency mode changed to FULL");
    }
    return AVCODEC_SAMPLE_ERR_OK;
}
```

## Additional Use Cases

In addition to high-speed playback, this capability can also improve performance and responsiveness in the following scenarios.

- **Load reduction and cooling in high-temperature scenarios**: When a device heats up and triggers a thermal alarm, controlling power consumption takes priority over maintaining a high frame rate. You can switch to `UNIFORM` mode and configure a lower frame retention ratio (for example, 0.3), reducing system load by lowering the decoding and display frame rates, thereby effectively assisting device cooling.
- **Improved drag smoothness in editing preview scenarios**: In scenarios such as video editing that require frequent progress bar dragging, decoding all intermediate frames can significantly slow down the screen refresh response. You can temporarily switch to `UNIFORM` mode in this state and configure a lower frame retention ratio, trading a moderate reduction in decoded intermediate frames for faster screen refresh speeds, thereby notably improving the responsiveness and smoothness of interactions.

**Example (responding to a thermal warning):**

<!-- @[onThermalWarningReceived](https://gitcode.com/openharmony/applications_app_samples/blob/master/code/BasicFeature/Media/AVCodec/entry/src/main/cpp/capabilities/video_decoder.cpp) -->

``` C++
int32_t VideoDecoder::OnThermalWarningReceived(double ratio)
{
    OH_AVFormat *param = OH_AVFormat_Create();
    CHECK_AND_RETURN_RET_LOG(param != nullptr, AVCODEC_SAMPLE_ERR_ERROR, "AVFormat create failed");

    // Use the UNIFORM mode.
    OH_AVFormat_SetIntValue(param, OH_MD_KEY_VIDEO_DECODER_FRAME_RETENTION_MODE,
                            OH_FRAME_RETENTION_MODE_UNIFORM);

    // Set the retention ratio (for example, 0.3 means only 30% of decoded frames are output).
    OH_AVFormat_SetDoubleValue(param, OH_MD_KEY_VIDEO_DECODER_FRAME_RETENTION_RATIO, ratio);

    // The configuration takes effect in real time, and the system performs uniform frame dropping to reduce the overall system load.
    int32_t ret = OH_VideoDecoder_SetParameter(decoder_, param);
    OH_AVFormat_Destroy(param);
    CHECK_AND_RETURN_RET_LOG(ret == AV_ERR_OK, AVCODEC_SAMPLE_ERR_ERROR,
                             "SetParameter failed, ret: %{public}d", ret);
    return AVCODEC_SAMPLE_ERR_OK;
}
```
