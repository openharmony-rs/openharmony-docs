This module defines the annotation types of OpenHarmony ArkTS APIs, such as the minimum available version of the lifecycle and suppressing warnings generated by APIs. It enables you to identify and manage API features such as compatibility and warning suppression. This module addresses issues such as version compatibility warnings, permission warnings, and multi-device adaptation warnings encountered during cross-version development and third-party SDK integration. Annotations are used to suppress unnecessary warnings, improving code maintainability and development efficiency.

> **NOTE**
>
> - The initial APIs of this module are supported since API version 22. Newly added APIs will be marked with a superscript to indicate their earliest API version.

## Modules to Import

```typescript
import { Available, SuppressWarnings, SuppressWarningsType } from '@kit.BasicServicesKit';
```

## Available

@interface Available { minApiVersion: string = '' }

Annotates the minimum available version supported by an API. This annotation capability can be used on classes, interfaces, functions, variables, types, modules, and enums. After the annotation is added to the source code, the compilation tool checks for potential compatibility issues. If the value of **minApiVersion** is greater than that of **compatibleSdkVersion** specified in **build-profile.json5**, a compatibility warning is reported.

**Widget capability**: This API can be used in ArkTS widgets since API version 22.

**Atomic service API**: This API can be used in atomic services since API version 22.

**Model restriction:** This API can be used only in the stage model.

**System capability**: SystemCapability.Base

<!--RP1-->
| Name | Type | Read-Only | Optional | Description                       |
| ---- | ---- | ---- | --- | -------------------------- |
| minApiVersion | string | No | No | Minimum available version, which consists of two parts: system type and version number. The system type can be omitted only when it is OpenHarmony, for example, **'OpenHarmony 20'** or **'20'**. If the value of **minApiVersion** is greater than that of **compatibleSDKVersion** specified in **build-profile.json5**, a compatibility warning is reported. |

**Example**

  ```typescript
  import { Available, deviceInfo } from '@kit.BasicServicesKit';

  @Available({minApiVersion: 'OpenHarmony 22'}) // Mark the minimum available version of the function.
  function myFunc() {}

  @Available({minApiVersion: '22'}) // Mark the minimum available version of the class. The default system type is OpenHarmony.
  class MyClass {}

  // Not recommended: If the compatibleSdkVersion value set in the build-profile.json5 file in the project root directory is less than 22, and the myFunc method is called directly without version check, the compiler reports a warning at the call site of myFunc, indicating that the method may fail to run on devices with earlier versions.
  myFunc();

  // Recommended approach 1: Use deviceInfo.sdkApiVersion to obtain the system software API version for the check, which avoids running exceptions on devices with earlier versions and eliminates the compilation warning.
  if (deviceInfo.sdkApiVersion >= 22) {
    myFunc();
  } else {
    // Select a method available on earlier versions based on the business logic.
  }

  // Recommended approach 2: Mark the @Available since version information on the parent function (or class) of the myFunc call site. When the newly marked version is not lower than the minimum available version of myFunc, the compilation warning is eliminated.
  @Available({minApiVersion: 'OpenHarmony 22'})
  function myNewFunc() {
    myFunc();
  }
  ```

## SuppressWarnings<sup>23+</sup>

@interface SuppressWarnings {

  rules: Array\<SuppressWarningsType>;

}  

Provides the API warning suppression capability, allowing developers to suppress warnings generated during API calls by using annotations. This capability can be applied to API elements such as classes, functions, variables, types, and interfaces. After the corresponding annotation is added to the source code, the compiler automatically suppresses the corresponding warning information based on the preset rules. It is suitable for scenarios where certain warnings need to be temporarily ignored to avoid distracting warnings from the compiler, helping developers focus on critical issues and improve development efficiency.

**Card capability**: This API can be used in ArkTS widgets since API version 23.

**Atomic service API**: This API can be used in atomic services since API version 23.

**Model restriction:** This API can be used only in the stage model.

**System capability**: SystemCapability.Base

| Name | Type | Read-Only | Optional | Description |
| ---- | ---- | ---- | --- | -------------------------- |
| rules | Array<[SuppressWarningsType](#suppresswarningstype23)> | No | No | Set of rules that support warning suppression, used to specify the warning types to be suppressed. Multiple rules can be passed in an array to suppress multiple types of warnings at the same time. For the available values, see [SuppressWarningsType](#suppresswarningstype23). |

**Example**

<!--RP2-->
Prerequisites for compatibility warning suppression: The value of **compatibleSdkVersion** in the **build-profile.json5** file under the project root directory is **20**.
<!--RP2End-->

Prerequisites for permission warning suppression: No permission is requested under **requestPermissions** in the **module.json5** file.

> **NOTE**
>
> When this annotation capability is used on a container node, warnings generated by its child nodes will be suppressed.
>
> When a warning is matched by multiple suppression rules, only the suppression rule closest to the code generating the warning takes effect. When different types of warnings are matched by different suppression rules, each suppression rule takes effect independently.

  ```typescript
  import { SuppressWarnings, SuppressWarningsType, systemDateTime } from '@kit.BasicServicesKit';
  import { photoAccessHelper } from '@kit.MediaLibraryKit';
  import { common } from '@kit.AbilityKit';
  // Compatibility warning suppression section.
  systemDateTime.getAutoTimeStatus();  // The API is available since version 21. Calling it directly generates a compatibility warning.
  // The 'getAutoTimeStatus' API is supported since SDK version 21. However, the current compatible SDK version is 20.

  @SuppressWarnings({rules: [SuppressWarningsType.COMPATIBILITY]})
  function myFunc() {
    systemDateTime.getAutoTimeStatus(); // After the @SuppressWarnings annotation is used, the compatibility warning is suppressed. When used for the myFunc() container node, the compatibility warning of the child node is also suppressed.
  }

  @SuppressWarnings({rules: [SuppressWarningsType.COMPATIBILITY]})
  class MyClass {
    status = systemDateTime.getAutoTimeStatus(); // After the @SuppressWarnings annotation is used, the compatibility warning is suppressed.
  }


  // Suppress the permission warning.
  async function savePhotoToGallery(context: common.UIAbilityContext) {
    let helper = photoAccessHelper.getPhotoAccessHelper(context);
    let uri = await helper.createAsset(photoAccessHelper.PhotoType.IMAGE, 'jpg');
    // To use this API, you need to apply for the permissions: ohos.permission.WRITE_IMAGEVIDEO
  }

  @SuppressWarnings({rules: [SuppressWarningsType.PERMISSION]})
  async function savePhotoToGallerySuppressCompatibility(context: common.UIAbilityContext) {
    let helper = photoAccessHelper.getPhotoAccessHelper(context);
    @SuppressWarnings({rules: [SuppressWarningsType.COMPATIBILITY]}) // If two types of suppression content exist at the same time, only the nearest suppression type takes effect. (The compatibility warning is suppressed, but the permission warning still exists.)
    let uri = await helper.createAsset(photoAccessHelper.PhotoType.IMAGE, 'jpg'); // After the @SuppressWarnings annotation is used, the compatibility warning is suppressed, but the permission warning still exists.
  }

  @SuppressWarnings({rules: [SuppressWarningsType.PERMISSION]})
  async function savePhotoToGallerySuppress(context: common.UIAbilityContext) {
    let helper = photoAccessHelper.getPhotoAccessHelper(context);
    let uri = await helper.createAsset(photoAccessHelper.PhotoType.IMAGE, 'jpg'); // After the @SuppressWarnings annotation is used, the permission warning is suppressed.
  }
  ```

// @SuppressWarnings \<SuppressWarningsType>

This capability supports quickly suppressing warnings with single-line comments. After a comment is added above the code line triggering the warning, the compiler automatically suppresses the corresponding warning based on the rules. The identifiers in comments must match the enumerated values of **SuppressWarningsType** (for example, **compatibility** corresponds to **COMPATIBILITY**) and take effect only for the code line immediately following it.

> **NOTE**
>
> Only single-line comment (//) format is supported. Example: // @SuppressWarnings compatibility
>
> Multi-line comment (/\*\*/) format is not supported. Example: /\* @SuppressWarnings compatibility */
>
> Warnings generated by the child nodes of the container node cannot be suppressed.

**Comment usage example**

<!--RP3-->
Prerequisites for compatibility warning suppression: The value of **compatibleSdkVersion** in the **build-profile.json5** file under the project root directory is **20**.
<!--RP3End-->

Prerequisites for permission warning suppression: No permission is requested under **requestPermissions** in the **module.json5** file.

  ```typescript
  import { systemDateTime } from '@kit.BasicServicesKit';
  import { photoAccessHelper } from '@kit.MediaLibraryKit';
  import { common } from '@kit.AbilityKit';
  // Compatibility warning elimination section
  systemDateTime.getAutoTimeStatus();  // The API is available since version 21. Calling it directly generates a compatibility warning.
  // The 'getAutoTimeStatus' API is supported since SDK version 21. However, the current compatible SDK version is 20.

  // @SuppressWarnings compatibility
  systemDateTime.getAutoTimeStatus();  // After the @SuppressWarnings annotation is used, the compatibility warning is suppressed.


  // Permission warning elimination section
  async function savePhotoToGallery(context: common.UIAbilityContext) {
    let helper = photoAccessHelper.getPhotoAccessHelper(context);
    let uri = await helper.createAsset(photoAccessHelper.PhotoType.IMAGE, 'jpg');
    // To use this API, you need to apply for the permissions: ohos.permission.WRITE_IMAGEVIDEO
  }
  // @SuppressWarnings permission
  async function savePhotoToGallerySuppressNoUse(context: common.UIAbilityContext) {
    let helper = photoAccessHelper.getPhotoAccessHelper(context);
    let uri = await helper.createAsset(photoAccessHelper.PhotoType.IMAGE, 'jpg'); // After the annotation is used, warnings of child nodes in the container cannot be eliminated and are still generated.
    // To use this API, you need to apply for the permissions: ohos.permission.WRITE_IMAGEVIDEO
  }

  async function savePhotoToGallerySuppress(context: common.UIAbilityContext) {
    let helper = photoAccessHelper.getPhotoAccessHelper(context);
    // @SuppressWarnings permission
    let uri = await helper.createAsset(photoAccessHelper.PhotoType.IMAGE, 'jpg'); // After the @SuppressWarnings annotation is used, the permission warning is suppressed.
  }
  ```

## SuppressWarningsType<sup>23+</sup>

Defines the warning types that support suppression. You can selectively suppress compatibility warnings, multi-device warnings, and permission warnings as required. This helps ensure code quality, reduce unnecessary warning interference, and improve development experience.

**Card capability**: This API can be used in ArkTS widgets since API version 23.

**Atomic service API**: This API can be used in atomic services since API version 23.

**Model restriction:** This API can be used only in the stage model.

**System capability**: SystemCapability.Base

| Name                   | Value   | Description                           |
| ---------------------- | ---- | ------------------------------ |
| COMPATIBILITY     | compatibility    | Supports suppression of compatibility warnings. A warning is generated when the API version of the called API is later than the compatible SDK version configured for the project. It is recommended to use this option when version checks or compatibility handling have been performed, to avoid suppressing warnings blindly and causing abnormal running on devices with earlier versions. |
| SYSCAP     | syscap    | Supports suppression of multi-device warnings. A warning is generated when the system capability of the called API is not supported on the target device. |
| PERMISSION     | permission    | Supports suppression of permission warnings. A warning is generated when an API that requires a permission is called but the corresponding permission is not declared in the configuration file.<br>**Since:** 26.0.0 |
