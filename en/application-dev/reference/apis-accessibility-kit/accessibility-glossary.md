## A

### Accessibility event

An event generated by the system accessibility service when a user operates the device or the UI changes. It identifies its category by event type (including accessibility event type, window change type, touch browsing event type, gesture event type, and page update type) and is dispatched to registered assistive extensions that match the event type for response.

### Accessibility extension

An extension capability type based on the ExtensionAbility framework, specifically used to implement accessibility assistance functions. Developers can handle accessibility events and key events in it, and query node information and inject gestures through the context. It is also called an assistive application.

### Accessibility focus

The focus state managed by the accessibility service, used to identify the interface element currently focused by an assistive function. Unlike the input focus, it is the starting point from which an assistive function (such as a screen reader) reads or operates interface elements.

### Accessibility Kit

An accessibility development kit provided by OpenHarmony, which includes modules such as assistive function management, assistive extension capability, assistive extension context, gesture path, and touch point. It is used to help developers build accessibility assistance applications and help users with visual or hearing impairments use devices more effectively.

### Accessibility node element

A component on the UI that can be accessed and operated by the accessibility service (such as a button or text input box), forming the accessibility node tree. An assistive extension obtains interface information and performs accessibility operations by querying node elements.

### Accessibility virtual node

A virtual node added by an assistive extension application to the accessibility node tree, used to represent custom UI elements or supplement the attribute information of existing nodes, so that the accessibility service can access and operate content that is not originally in the system node tree.

### Animation reduction

One of the accessibility assistance modes. After enabling, the system reduces or simplifies interface animation effects, used to help users who are sensitive to motion (such as those with vestibular disorders) reduce discomfort.

### Auto-broadcasting

The capability of an application to proactively broadcast content to users through the accessibility service, without requiring manual navigation by the user. Unlike broadcasting that passively responds to interface changes, it is used to proactively notify users at key business moments, such as operation completion or status changes.

### Auto-focusing

The capability of an application to actively move the accessibility focus to a specified element through the accessibility service, as opposed to focusing through manual user navigation. It is used to guide users to pay attention to specific interface elements.

## C

### Color inversion

An accessibility assistance feature. After enabling, the system inverts the screen display colors, used to help users with specific visual impairments read interface content more comfortably in inverted color mode.

## D

### Daltonization; Color correction

One of the accessibility assistance functions. It applies corresponding color filters to correct the colors displayed on the screen for different types of color vision deficiency (protanopia, deuteranopia, and tritanopia), helping users with color vision deficiency identify color information.

### Default focus

The element that an accessibility service prioritizes for focus when a window opens. An application can customize a list of default focus element IDs to help the accessibility service quickly locate the most critical element after the UI loads, improving interaction efficiency for users with special needs.

## F

### Flash alerts

One of the accessibility assistance modes. After enabling, the system alerts the user to events such as alarms, notifications, and incoming calls by flashing the screen or the flashlight, used to help users with hearing impairments perceive audible reminders.

## G

### Gesture injection

The capability of an assistive extension application to simulate user touch gestures (such as tap and swipe) to perform touch interactions, used to help assistive function applications complete UI operations on behalf of the user.

## H

### High-contrast text

One of the accessibility assistance features. After enabling, the system renders text with higher contrast, enhancing the visual difference between text and background, used to help low-vision users read text more clearly.

## M

### Magnification

One of the accessibility assistance features. After enabling, it magnifies the on-screen content and relies on the magnification gesture. It is used to help users with low vision zoom in on specific parts of the interface.

### Mono audio

One of the accessibility assistance modes. After enabling, it merges the left and right channel audio into mono output, used to help users with single-ear hearing impairment obtain complete audio information.

## S

### Screen reader

One of the accessibility assistance modes. After enabling, the system reads the interface content aloud to the user. It is the primary interaction method for visually impaired users to operate the device, and is usually used together with touch browsing mode.

### Senior mode

A care mode for elderly users. After enabling, it simplifies interface interactions to suit the usage habits of elderly users. It can be configured at the system level and the application level respectively. The system care mode is managed through the config module, and the application's own senior mode is managed through application interfaces.

## T

### Touch guide

An interaction mode in accessibility assistance functions. In this mode, users explore interface elements by touch instead of directly activating them, and the system reads aloud the element information at the current touch position. It is a companion interaction method for the screen reader feature.

### Touch mode

An operation mode under touch browsing, divided into single-tap mode (responds on touch) and double-tap mode (requires double-tap to confirm), used to adjust the interaction response of touch browsing according to user habits.
