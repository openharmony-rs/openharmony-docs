The ErrorManager module provides global observation capabilities for various runtime exceptions of applications, including registering and unregistering error observers. It is mainly used to monitor error scenarios such as application crashes (JS_CRASH), application freezes (APP_FREEZE), uncaught Promise exceptions, and resource over-baseline. By setting listeners, developers can capture exception information in real time, trace the root cause of problems, and record key metrics, thereby improving the stability monitoring capability of applications, accelerating fault diagnosis and localization efficiency, and enhancing application quality and user experience.

> **NOTE**
> 
> The initial APIs of this module are supported since API version 9. Newly added APIs will be marked with a superscript to indicate their earliest API version.

## Modules to Import
```ts
import { errorManager } from '@kit.AbilityKit';
```

## errorManager.on('error')

on(type: 'error', observer: ErrorObserver): number

Registers an error observer. After registration, it can capture JS_CRASH generated by the application, which is a type of application crash. When the observer captures this exception, the application does not exit. You are advised to add a synchronous exit operation after the callback function finishes executing.

This API can only be used in the main thread. If a thread error occurs, an error code is thrown. You are advised to handle it with try-catch logic.

Paired call: used together with the [errorManager.off('error')](#errormanagerofferror) method. After use, you can call the off method to unregister the listener.

**Atomic service API**: This API can be used in atomic services since API version 11.

**System capability**: SystemCapability.Ability.AbilityRuntime.Core

**Parameters**

| Name| Type| Mandatory| Description|
| -------- | -------- | -------- | -------- |
| type | string | Yes| Event type. It is fixed at **'error'**.|
| observer | [ErrorObserver](js-apis-inner-application-errorObserver.md) | Yes| Error observer instance.|

**Return value**

| Type| Description|
| -------- | -------- |
| number | Unique index of the observer, which corresponds one-to-one with the observer. This value can be used as the **observerId** parameter in the **errorManager.off** function.|

**Error codes**

For details about the error codes, see [Universal Error Codes](../errorcode-universal.md) and [Ability Error Codes](errorcode-ability.md).

| ID| Error Message|
| ------- | -------- |
| 401      | Parameter error. Possible causes: 1. Mandatory parameters are left unspecified; 2. Incorrect parameter types; 3. Parameter verification failed. |
| 16000003 | The specified ID does not exist. |

**Example**

```ts
import { errorManager } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';

let observer: errorManager.ErrorObserver = {
  onUnhandledException(errorMsg) {
    console.info('onUnhandledException, errorMsg: ', errorMsg);
  },
  onException(errorObj) {
    console.info('onException, name: ', errorObj.name);
    console.info('onException, message: ', errorObj.message);
    if (typeof(errorObj.stack) === 'string') {
      console.info('onException, stack: ', errorObj.stack);
    }
  }
};
let observerId = -1;

try {
  observerId = errorManager.on('error', observer);
} catch (paramError) {
  let code = (paramError as BusinessError).code;
  let message = (paramError as BusinessError).message;
  console.error(`error: ${code}, ${message}`);
}
```

## errorManager.on('globalErrorOccurred')<sup>18+</sup>

on(type: 'globalErrorOccurred', observer: GlobalObserver): void

Registers the `errorManager.on` API in any thread of the process to listen for exceptions in any thread across the entire process. When the observer captures this exception, the application does not exit. You are advised to add a synchronous exit operation after the callback function finishes executing.

Developers need to maintain the lifecycle of the custom exception handling callback function by themselves to ensure that the custom exception handling callback function is not released when an exception callback occurs.

Paired call: used together with the [errorManager.off('globalErrorOccurred')](#errormanageroffglobalerroroccurred18) method. After use, you can call the off method to unregister the listener.

**Atomic service API**: This API can be used in atomic services since API version 18.

**System capability**: SystemCapability.Ability.AbilityRuntime.Core

**Parameters**

| Name| Type| Mandatory| Description|
| -------- | -------- | -------- | -------- |
| type | string | Yes| Error observer. It is fixed at **'globalErrorOccurred'**.|
| observer | [GlobalObserver](#globalobserver18) | Yes | Custom exception handling callback function, used to receive global exception events. Callback function input parameter: (reason: GlobalError) => void, where reason is an object containing the exception name, message, stack, thread name, and type. |

**Error codes**

For details about the error codes, see [Universal Error Codes](../errorcode-universal.md) and [Ability Error Codes](errorcode-ability.md).

| ID| Error Message|
| ------- | -------- |
| 401      | Parameter error. Possible causes: 1. Mandatory parameters are left unspecified; 2. Incorrect parameter types; 3. Parameter verification failed. |
| 16200001 | If the caller is invalid. |

**Example**

```ts
import { errorManager } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';

const errorFunc = (observer: errorManager.GlobalError) => {
  console.info('result name :' + observer.name);
  console.info('result message :' + observer.message);
  console.info('result stack :' + observer.stack);
  console.info('result instanceName :' + observer.instanceName);
  console.info('result instanceType :' + observer.instanceType);
};

try {
  errorManager.on('globalErrorOccurred', errorFunc);
} catch (paramError) {
  let code = (paramError as BusinessError).code;
  let message = (paramError as BusinessError).message;
  console.error(`error: ${code}, ${message}`);
}
```

## errorManager.off('globalErrorOccurred')<sup>18+</sup>

off(type: 'globalErrorOccurred', observer?: GlobalObserver): void

Unregisters the error observer, unregistering the callback global listener currently registered in the same thread.

If the observer passed in is not in the observer queue registered via the **on** API, error code 16300004 is thrown. Therefore, you are advised to handle this using **try-catch** logic.

You are advised to call the unregister error observer API when the process is recycled. Otherwise, if another thread sends an exception callback, a crash may occur because the custom exception handling callback function cannot be found.

Paired call: used together with the [errorManager.on('globalErrorOccurred')](#errormanageronglobalerroroccurred18) method.

**Atomic service API**: This API can be used in atomic services since API version 18.

**System capability**: SystemCapability.Ability.AbilityRuntime.Core

**Parameters**

| Name| Type| Mandatory| Description|
| -------- | -------- | -------- | -------- |
| type | string | Yes| Set to 'globalErrorOccurred' to indicate an error observer.|
| observer | [GlobalObserver](#globalobserver18) | No | Custom exception handling callback function registered by the on method. Recommended usage. If this parameter is not passed, all observers registered by the on method are cleared; if this parameter is passed, only the specified observer is deleted. |

**Error codes**

For details about the error codes, see [Universal Error Codes](../errorcode-universal.md) and [Ability Error Codes](errorcode-ability.md).

| ID| Error Message|
| ------- | -------- |
| 401      | Parameter error. Possible causes: 1. Mandatory parameters are left unspecified; 2. Incorrect parameter types; 3. Parameter verification failed.   |
| 16200001 | If the caller is invalid. |
| 16300004 | If the observer does not exist. |

**Example**

```ts
import { errorManager } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';

const errorFunc = (observer: errorManager.GlobalError) => {
  console.info('result name :' + observer.name);
  console.info('result message :' + observer.message);
  console.info('result stack :' + observer.stack);
  console.info('result instanceName :' + observer.instanceName);
  console.info('result instanceType :' + observer.instanceType);
}

try {
  errorManager.off('globalErrorOccurred', errorFunc)
} catch (paramError) {
  let code = (paramError as BusinessError).code;
  let message = (paramError as BusinessError).message;
  console.error(`error: ${code}, ${message}`);
}
```

## errorManager.off('error')

| -------- | -------- | -------- | -------- |
| type | string | Yes| Event type. It is fixed at **'error'**.|
| observerId | number | Yes| Index of the observer returned by **on()**.|
| callback | AsyncCallback\<void> | Yes| Callback used to return the result.|

**Error codes**

For details about the error codes, see [Universal Error Codes](../errorcode-universal.md) and [Ability Error Codes](errorcode-ability.md).

| ID| Error Message|
| ------- | -------- |
| 401      | Parameter error. Possible causes: 1. Mandatory parameters are left unspecified; 2. Incorrect parameter types; 3. Parameter verification failed.   |
| 16000003 | The specified ID does not exist. |

**Example**


## errorManager.on('loopObserver')<sup>12+</sup>

on(type: 'loopObserver', timeout: number, observer: LoopObserver): void

Registers an observer for the message processing duration of the main thread. After the registration, the execution time of a message processed by the main thread of the application can be captured.

This API monitors the time interval from the start to the completion of each message and triggers the callback when the execution time exceeds the specified timeout threshold.

This API can only be used in the main thread. If a thread error occurs, an error code is thrown. You are advised to handle it with try-catch logic.

Paired call: used with the [errorManager.off('loopObserver')](#errormanageroffloopobserver12) method. After use, call the off method to unregister the listener and release resources.

**Atomic service API**: This API can be used in atomic services since API version 12.

**System capability**: SystemCapability.Ability.AbilityRuntime.Core

**Parameters**

| Name| Type| Mandatory| Description|
| -------- | -------- | -------- | -------- |
| type | string | Yes| Event type. It is fixed at **'loopObserver'**, indicating an observer for the message processing duration of the main thread.|
| timeout | number | Yes|  Event execution threshold, in milliseconds. The value must be greater than **0**.|
| observer | [LoopObserver](js-apis-inner-application-loopObserver.md) | Yes | Registers a listener for the time consumed by message handling on the main thread. Defines the onLoopTimeOut method, which is called when the message handling time on the main thread exceeds the threshold. |

**Error codes**

For details about the error codes, see [Universal Error Codes](../errorcode-universal.md).

| ID| Error Message|
| ------- | -------- |
| 401      | Parameter error. Possible causes: 1. Mandatory parameters are left unspecified; 2. Incorrect parameter types; 3. Parameter verification failed. |

**Example**

```ts
import { errorManager } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';

let observer: errorManager.LoopObserver = {
  onLoopTimeOut(timeout: number) {
    console.info('Duration timeout: ' + timeout);
  }
};

try {
  errorManager.on('loopObserver', 1, observer);
} catch (paramError) {
  let code = (paramError as BusinessError).code;
  let message = (paramError as BusinessError).message;
  console.error(`error: ${code}, ${message}`);
}
```

## errorManager.on('freeze')<sup>18+</sup>

on(type: 'freeze', observer: FreezeObserver): void

Registers an observer for the main thread freeze event of the application. If the observer is registered multiple times, only the last one takes effect.

This API can only be used in the main thread. If a thread error occurs, an error code is thrown. You are advised to handle it with try-catch logic.

Paired call: used in coordination with the [errorManager.off('freeze')](#errormanagerofffreeze18) method. After use, call the off method to unregister the listener.

> **NOTE**
>
> If the execution time of this callback function exceeds 1s, the [AppRecovery](./js-apis-app-ability-appRecovery.md) feature may become unavailable. The execution duration of the callback function can be calculated by parsing the time difference between "begin" and "Freeze callback execution completed" in the hilog logs. If it exceeds 1 second, you can try to optimize the callback logic by using asynchronous processing, reducing blocking operations, and optimizing data structures to reduce the execution duration.
>
> Do not use this API together with [errorManager.setDefaultFreezeObserver](#errormanagersetdefaultfreezeobserver). Mixing them may cause the registered callback function to fail to execute.

**Atomic service API**: This API can be used in atomic services since API version 18.

**System capability**: SystemCapability.Ability.AbilityRuntime.Core

**Parameters**

| Name| Type| Mandatory| Description|
| -------- | -------- | -------- | -------- |
| type | string | Yes| Event type. It is fixed at **'freeze'**, indicating an observer for the freeze event of the main thread.|
| observer | [FreezeObserver](#freezeobserver18) | Yes| Observer to register.|

**Error codes**

For details about the error codes, see [Universal Error Codes](../errorcode-universal.md).

| ID| Error Message|
| ------- | -------- |
| 401      | Parameter error. Possible causes: 1. Mandatory parameters are left unspecified; 2. Incorrect parameter types; 3. Parameter verification failed.   |

**Example**

```ts
import { errorManager } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';

const freezeCallback = () => {
  console.info('freezecallback');

try {

  let message = (paramError as BusinessError).message;
```

| ID| Error Message|
| ------- | -------- |

## errorManager.setDefaultErrorHandler<sup>21+</sup>

setDefaultErrorHandler(defaultHandler?: ErrorHandler): ErrorHandler

Returns the previously registered handler when a JavaScript crash exception occurs. It can only be used in the main thread.

If an invalid parameter is passed or the API is called from a child thread, an error code is thrown and **undefined** is returned. You are advised to handle it with try-catch logic.

If the API parameter is empty, subsequently registered handlers are not able to establish a connection with previously registered handlers, thereby breaking the chain call mechanism.

The chained call mechanism allows multiple error handlers to be executed in sequence: when a new handler is registered, the previously registered handler is returned; in a handler, the preceding handler can be called to form a handler chain. This enables the stacking of multi-layer error handling logic, ensuring that each handler is executed as expected.

**Atomic service API**: This API can be used in atomic services since API version 21.

**System capability**: SystemCapability.Ability.AbilityRuntime.Core

**Parameters**

| Name| Type| Mandatory| Description|

| defaultHandler | [ErrorHandler](#errorhandler21) | No| Newly registered error handler. The default value is empty.|

**Return value**

| Type| Description|
| -------- | -------- |
| [ErrorHandler](#errorhandler21) | Previously registered error handler.|

**Error codes**

For details about the error codes, see [Ability Error Codes](errorcode-ability.md).

| ID| Error Message|
| ------- | -------- |
| 16000205      | The API is not called on the main thread. |

**Example**

```ts
import { errorManager } from '@kit.AbilityKit';
import { process } from '@kit.ArkTS';

let oldHandler: errorManager.ErrorHandler;
```

## errorManager.setDefaultFreezeObserver

setDefaultFreezeObserver(defaultObserver?: FreezeObserver) : FreezeObserver

When APP_FREEZE occurs, supports chained callbacks and returns the previously registered handler. This API can be called only from the main thread.

If an invalid parameter is passed in or this API is called from a child thread, an error code is thrown and undefined is returned. Therefore, it is recommended that you use try-catch logic for handling.

> **NOTE**
>

> 2. On the first registration, the previously registered handler is null.
> 
> Do not use this API together with [on('freeze')](#errormanageronfreeze18) or [off('freeze')](#errormanagerofffreeze18).

**Since:** 26.0.0

**Parameters**

| Name | Type | Mandatory | Description |
| -------- | -------- | -------- | -------- |
| defaultObserver | [FreezeObserver](#freezeobserver18) | No | Newly registered freeze observer. The default value is null.<br>When this parameter is null, the subsequently registered handler cannot be associated with the previously registered handler, which interrupts the chained call.|

**Return value**

| Type | Description |
| -------- | -------- |
| [FreezeObserver](#freezeobserver18) | Returns the previously registered handler. |

**Error codes**

For details about the error codes, see [Ability Error Codes](errorcode-ability.md).

| ID | Error Message |
| ------- | -------- |
| 16000205 | The API is not called on the main thread. |

**Example**

```ts
import { errorManager } from '@kit.AbilityKit';
import { BusinessError } from '@kit.BasicServicesKit';

// Save the previously registered handler. If this is the first registration, there is no previous handler.
let oldHandler: errorManager.FreezeObserver = () => {};
const freezeHandler: errorManager.FreezeObserver = () => {
  // Implement the custom FreezeHandler logic.
  console.info('[freezeHandler] freeze handler invoked.');
  if (oldHandler) {
    oldHandler();
  } else {
    console.info('[freezeHandler] freeze handler end.');
  }
};

export function setFreezeHandler() {
  try {
    oldHandler = errorManager.setDefaultFreezeObserver(freezeHandler);
  } catch (paramError) {
    let code = (paramError as BusinessError).code;
    let message = (paramError as BusinessError).message;
    console.error(`Failed to set freeze handler. Code: ${code}, message: ${message}`);
  }
  console.info('Registered freeze Handler.');
```
