Defines the data structure of a [notification request](../../notification/notification-glossary.md#notification-request), which is used to describe all information of a notification, including [notification content](../../notification/notification-glossary.md#notification-content), identifier, display style, interaction behavior, and so on.

> **NOTE**
>
> The initial APIs of this module are supported since API version 7. Newly added APIs will be marked with a superscript to indicate their earliest API version.

## NotificationRequest

Defines the data structure of a [notification request](../../notification/notification-glossary.md#notification-request), which is used to describe all information of a notification, including [notification content](../../notification/notification-glossary.md#notification-content), identifier, display style, interaction behavior, and so on.

**System capability**: SystemCapability.Notification.Notification

| Name                           | Type                                                   |  Read Only| Optional| Description                                                                         |
| ---------------------------------- | -------------------------------------------------------- | ----- | --- |-------------------------------------------------------------------------------|
| content                       | [NotificationContent](js-apis-inner-notification-notificationContent.md#notificationcontent-1)   |   No  | No  | Notification display content, including the notification title and body.                              |
| id                            | number                                                   |   No | Yes | Notification ID. The default value is **0**. If a notification with the same ID exists, the notification is updated. If no notification with the same ID exists, a new notification is created.|
| updateOnly<sup>18+</sup>      | boolean                                                  |   No | Yes | Whether to update notifications only. The default value is **false**.<br> - **true**: If a notification with the same ID exists, the notification is updated. If no notification with the same ID exists, the update fails and no new notification is created.<br> - **false**: If a notification with the same ID exists, the notification is updated. If no notification with the same ID exists, a new notification is created.        |
| appMessageId<sup>12+</sup>       | string                                                |   No  | Yes  | Unique identifier field carried when an application sends a notification, used for notification deduplication. If the same application publishes notifications carrying the same **appMessageId** through different channels such as local and cloud, the device displays only one message, and subsequent duplicate notifications received will be silently deduplicated without being displayed or alerted. The deduplication identifier is valid only within 24 hours after the notification is published, and becomes invalid after 24 hours or after the device restarts.<br>The size does not exceed 202 bytes, and the excess part will be truncated. The value is empty by default. |
| notificationSlotType<sup>11+</sup> | [notificationManager.SlotType](js-apis-notificationManager.md#slottype) |   No  | Yes  | Type of the [notification channel](../../notification/notification-glossary.md#notification-slot). The default value is OTHER_TYPES. Different channel types have different [notification reminder modes](../../notification/notification-glossary.md#notification-reminder-mode). |
| notificationFlags<sup>8+</sup> | [NotificationFlags](js-apis-inner-notification-notificationFlags.md) |   No  | Yes  | [Notification flag](../../notification/notification-glossary.md#notification-flags) settings. Empty by default. This parameter becomes writable since API version 23. Setting this parameter can reduce the notification reminder modes. When the notification channel type is [LIVE_VIEW](js-apis-notificationManager.md#slottype), setting this parameter does not take effect. |
| priorityNotificationType<sup>23+</sup>  | [notificationManager.PriorityNotificationType](js-apis-notificationManager.md#prioritynotificationtype23)   | No | Yes | Notification priority type. The default value is OTHER. Setting this parameter can pin the notification to the top and display it prominently in the [notification center](../../notification/notification-glossary.md#notification-center). <!--RP2--><!--RP2End-->The actual display effect depends on device capabilities and the notification center UI style.<br>**Model constraint:** This API can be used only in the stage model. |
| isAlertOnce                   | boolean                                                  |   No | Yes | Whether to send a notification only once when the notification is published or updated. The default value is **false**.<br> - **true**: A notification is sent only when the notification is published for the first time. For subsequent update, the notification mode is changed to [LEVEL_LOW](js-apis-notificationManager.md#slotlevel).<br> - **false**: A notification is sent based on the configured notification mode.                                                       |
| sound<sup>12+</sup>           | string                                                   |   No  | Yes  | Resource path of the application notification [customized ringtone](../../notification/notification-glossary.md#customized-ringtone). Empty by default. Two audio resource sources are supported:<br/> - Resource file: a preset audio file of the application. The resource file must be placed in the resources/rawfile directory, and the file name is passed in directly when used.<br/> - Sandbox file: an audio file downloaded from the network or generated by the user. It must be placed in the files directory or its subdirectories in the EL1 area of the [sandbox file directory](../../file-management/app-sandbox-directory.md#application-file-directory-and-application-file-path). The format passed in is uri::{fileUri}, where fileUri is the path obtained through [getUriFromPath](../apis-core-file-kit/js-apis-file-fileuri.md#fileurigeturifrompath). For example, the application passes the downloaded audio resource demo.mp3 into the sandbox file directory /data/storage/el1/base/files/, and the path obtained through getUriFromPath is file://{bundleName}/data/storage/el1/base/files/demo.mp3. Publishing a notification with this path plays the audio resource downloaded by the application.<br/>Formats such as m4a, aac, mp3, ogg, wav, flac, and amr are supported.|
| badgeNumber<sup>9+</sup>      | number                                                   |   No  | Yes  | Number of notifications displayed on the application icon. The number is displayed cumulatively. The default value is 0.<br>When the value of `badgeNumber` is less than or equal to 0, this badge setting is ignored.<br>When the cumulative badge number is greater than 99, the [notification badge](../../notification/notification-glossary.md#notification-badge) displays 99+.<br>For example, if the application publishes three notifications and sets `badgeNumber` to 2, 0, and 3 in sequence, the application displays 2, 2, and 5 in sequence.|
| wantAgent                     | [WantAgent](../apis-ability-kit/js-apis-app-ability-wantAgent.md)            |   No | Yes | Behavior intent of an application, which is triggered when a notification is clicked. This parameter is left empty by default.                  |
| actionButtons                 | Array\<[NotificationActionButton](js-apis-inner-notification-notificationActionButton.md)\>             |   No  | Yes  | [Notification buttons](../../notification/notification-glossary.md#notification-button). Since API version 16, a notification on a `wearable` device can contain at most three buttons.                                                          |
| removalWantAgent<sup>9+</sup> | [WantAgent](../apis-ability-kit/js-apis-app-ability-wantAgent.md)            |   No | Yes | Behavior intent of an application, which is triggered when a notification is removed. Only common events can be published (that is, the **actionType** field of [WantAgentInfo](../apis-ability-kit/js-apis-inner-wantAgent-wantAgentInfo.md#wantagentinfo-1) is set to **4**).                                         |
| tapDismissed                  | boolean                                                  |   No | Yes | Whether the notification is automatically cleared when the notification carries **wantAgent** or **actionButtons**. This parameter is valid only when the notification carries **wantAgent** or **actionButtons**. The default value is **true**.<br> - **true**: The current notification is automatically cleared after the notification or button is tapped.<br> - **false**: The current notification is retained after the notification or button is tapped.|
| autoDeletedTime               | number                                                   |   No  | Yes  | Scheduled auto-delete time for the notification. This parameter does not take effect if a value less than 0 or a past time is passed in.<br>Data format: timestamp.<br>Unit: millisecond.<br>For example, to delete a notification after it has been retained for 3 seconds (3000 ms), the corresponding deletion time is: **new Date().getTime()** + 3000.|
| deliveryTime                  | number                                                   |   No  | Yes  | Notification delivery time. This parameter is automatically generated by the system and does not require configuration.<br>Data format: timestamp.<br>Unit: millisecond.      |
| label                         | string                                                   |   No  | Yes  | Notification label.<br>The **label** field functions similarly to an ID and can be used alone or combined with the ID to serve as the notification identifier. The actual display effect depends on device capabilities and the notification center UI style<!--RP1--><!--RP1End-->.                                                 |
| overlayIcon<sup>23+</sup>      | [image.PixelMap](../apis-image-kit/arkts-apis-image-PixelMap.md)            |   No  | Yes  | Overlay icon of the notification, which replaces the icon on the left of the notification. ## DistributedOptions<sup>8+</sup>

Describes the [cross-device collaboration](../../notification/notification-glossary.md#cross-device-collaboration) options. This is a reserved capability and is not yet supported.

**System capability**: SystemCapability.Notification.Notification

| Name                  | Type           | Read Only| Optional| Description                              |
| -----------------------| -------------- | ---- | ---- | --------------------------------- |
| isDistributed          | boolean        | No  | Yes  | Whether cross-device notifications are supported. The default value is **true**.<br> - **true**: cross-device notifications are supported.<br> - **false**: cross-device notifications are not supported.                 |
| supportDisplayDevices  | Array\<string> | No  | Yes  | List of the devices to which the notification can be synchronized.          |
| supportOperateDevices  | Array\<string> | No  | Yes  | List of the devices on which the notification can be opened.            |

## NotificationParameters<sup>24+</sup>

Describes part of the **wantAgent** information in [NotificationRequest](#notificationrequest-1).

**Model restriction**: This API can be used only in the stage model.

**System capability**: SystemCapability.Notification.Notification

| Name                  | Type           | Read Only| Optional| Description                              |
| -----------------------| -------------- | ---- | ---- | --------------------------------- |
| wantAction          | string        | No  | Yes  | **action** field passed in **want** when **wantAgent** is created. For details, see [action](../apis-ability-kit/js-apis-app-ability-want.md#want).|
| wantUri  | string | No  | Yes  | **uri** field passed in **want** when **wantAgent** is created. For details, see [uri](../apis-ability-kit/js-apis-app-ability-want.md#want).|
| wantParameters  | Record\<string, Object> | No  | Yes  | **parameters** field passed in **want** when **wantAgent** is created. For details, see [parameters](../apis-ability-kit/js-apis-app-ability-want.md#want).|
