This module provides the accessibility hover event capability. After accessibility mode is enabled, touch events are converted to accessibility hover events. Developers can listen for these events to respond to single-finger touch interactions in accessibility mode, which is suitable for scenarios where the accessibility of an application needs to be improved for users with disabilities. This module provides the **onAccessibilityHover** and **onAccessibilityHoverTransparent** APIs for listening to and processing hover events generated by single-finger touch in accessibility mode. It is suitable for component development scenarios where touch interaction accessibility support needs to be provided for visually impaired users. Developers can use this module to capture touch events of components that cannot be focused by accessibility, thereby improving the accessibility of the application.

>  **NOTE**
>
>  - This event is supported since API version 12. New APIs added in later versions will be marked with a superscript to indicate their earliest API version.
>
>  - The APIs of this module can be used only in the stage model.
>
>  - Currently, accessibility hover events can be triggered only when accessibility mode is enabled.

## onAccessibilityHover

onAccessibilityHover(callback: AccessibilityCallback): T

Triggered in accessibility mode when a single finger touches the bound component.

> **NOTE**
>
> This API is complementary to [onAccessibilityHoverTransparent](#onaccessibilityhovertransparent20): **onAccessibilityHover** processes hover events of components that can be identified as focusable by accessibility (the callback parameter is **AccessibilityHoverEvent**), while **onAccessibilityHoverTransparent** processes touch events of components that cannot be identified as focusable by accessibility (the callback parameter is **TouchEvent**). Only one of the two callbacks is triggered for the same component at a time. To listen for both types of components, bind the two APIs to different components. This API cannot be called in [attributeModifier](ts-universal-attributes-attribute-modifier.md#attributemodifier).

**Atomic service API**: This API can be used in atomic services since API version 12.

**System capability**: SystemCapability.ArkUI.ArkUI.Full

**Parameters**

| Name       | Type                   | Mandatory | Description                         |
| ---------- | -------------------------- | ------- | ----------------------------- |
| callback      | [AccessibilityCallback](#accessibilitycallback) | Yes   |  Callback invoked when a single-finger touch is performed on the focusable component bound to this callback that can be recognized by accessibility after Accessibility Mode is enabled. |

**Return value**

| Type| Description|
| -------- | -------- |
| T | Current component.|

## AccessibilityCallback

type AccessibilityCallback = (isHover: boolean, event: AccessibilityHoverEvent) => void

Defines the callback type for accessibility hover events, active in accessibility mode.

**Atomic service API**: This API can be used in atomic services since API version 12.

**System capability**: SystemCapability.ArkUI.ArkUI.Full

**Parameters**

| Name             | Type                               | Mandatory| Description                                                        |
| ------------------- | ----------------------------------- | ---- | ------------------------------------------------------------ |
| isHover             | boolean                             | Yes  | Hover state. **true**: The finger enters the component. **false**: The finger exits the component.|
| event | [AccessibilityHoverEvent](#accessibilityhoverevent) | Yes | Accessibility hover event object, which is used to obtain detailed information when the accessibility hover event is triggered, including the accessibility hover action type (type), the coordinates of the finger relative to the component/window/screen (x, y, windowX, windowY, displayX, displayY, globalDisplayX, globalDisplayY), and other attributes. |

## onAccessibilityHoverTransparent<sup>20+</sup>

onAccessibilityHoverTransparent(callback: AccessibilityTransparentCallback): T

This callback is triggered when a screen-reading accessibility application (such as a screen reader) is enabled, a finger touches the component area, and neither the component nor any of its child components is identified as focusable by the accessibility hover event. The callback parameter returns the **TouchEvent** corresponding to the touch event. Only single-finger touch is supported. Scenarios where the touch position is within the area of the following components are not supported, including [UIExtension](../../apis-arkui/js-apis-arkui-uiExtension.md), [Web](../../apis-arkweb/arkts-basic-components-web.md), <!--Del-->[FormComponent](ts-basic-components-formcomponent-sys.md), <!--DelEnd-->[XComponent](ts-basic-components-xcomponent.md), and scenarios integrated with third-party UI frameworks. In the preceding scenarios, this callback API does not take effect.

The main reasons why a component cannot be identified as focusable by the accessibility hover event are as follows: The [accessibilityLevel](ts-universal-attributes-accessibility.md#accessibilitylevel) attribute of the component is set to **no** or **no-hide-descendants**; the component has no text and no [accessibilityText](ts-universal-attributes-accessibility.md#accessibilitytext) configured, and does not support the tap or long press operation.

> **NOTE**
>
> This API is complementary to [onAccessibilityHover](#onaccessibilityhover). Only one of the two callbacks is triggered for the same component at a time. This API cannot be called in [attributeModifier](ts-universal-attributes-attribute-modifier.md#attributemodifier).

**Atomic service API**: This API can be used in atomic services since API version 20.

**System capability**: SystemCapability.ArkUI.ArkUI.Full

**Parameters**
| Name       | Type                   | Mandatory | Description                         |
| ---------- | -------------------------- | ------- | ----------------------------- |
| callback      | [AccessibilityTransparentCallback](#accessibilitytransparentcallback20) | Yes   |  Provides the touch events of user input that fail to be responded to after a screen reader is enabled. This callback is triggered when a finger touches the component area and neither the component nor any of its child components is recognized as focusable by Accessibility Hover. |

**Return value**

| Type| Description|
| -------- | -------- |
| T | Current component.|

## AccessibilityTransparentCallback<sup>20+</sup>

type AccessibilityTransparentCallback = (event: TouchEvent) => void

Provides the callback type for touch events that are not responded to by the accessibility hover event after a screen-reading accessibility application is enabled.

**Atomic service API**: This API can be used in atomic services since API version 20.

**System capability**: SystemCapability.ArkUI.ArkUI.Full

**Parameters**

| Name             | Type                               | Mandatory| Description                                                        |
| ------------------- | ----------------------------------- | ---- | ------------------------------------------------------------ |
| event | [TouchEvent](ts-universal-events-touch.md#touchevent)| Yes   | Original TouchEvent object, used to obtain the detailed information of a touch event that cannot be recognized by accessibility hover as a focusable component, including touch point coordinates, touch type, and other attributes. <br>**Note:** The touch event type [TouchType](ts-appendix-enums.md#touchtype) of the TouchEvent object is one of the four accessibility hover event types, namely HOVER_ENTER, HOVER_MOVE, HOVER_EXIT, and HOVER_CANCEL. |

## Example

### Example 1: Using the onAccessibilityHover Event

This example demonstrates how to use the **onAccessibilityHover** event to configure a button in accessibility mode.

```ts
// xxx.ets
@Entry
@Component
struct OnAccessibilityHoverEventExample {
  @State hoverText: string = 'no hover';
  @State color: Color = Color.Blue;

  build() {
    Column({ space: 20 }) {
      Button(this.hoverText)
        .width(180).height(80)
        .backgroundColor(this.color)
        .onAccessibilityHover((isHover: boolean) => {
          // Dynamically modify the text content and background color of the button when the accessibility hover event (finger touch enter/exit) occurs through the onAccessibilityHover event.
          if (isHover) {
            this.hoverText = 'hover';
            this.color = Color.Pink;
          } else {
            this.hoverText = 'no hover';
            this.color = Color.Blue;
          }
        })
    }.padding({ top: 30 }).width('100%')
  }
}
```

### Example 2: Capturing a Touch Event on a Non-Focusable Component

This example shows how to capture touch events from a component that cannot receive focus in accessibility mode using the **onAccessibilityHoverTransparent** API and display event details in the text area below.

Starting from API version 20, the [onAccessibilityHoverTransparent](#onaccessibilityhovertransparent20) API with the input parameter type **AccessibilityTransparentCallback** has been added.

```ts
@Entry
@Component
struct OnAccessibilityHoverTransparentExample {
  @State text: string = '';
  @State eventType: string = '';

  build() {
    Column({ space: 50 }) {
      Column() {
        Button('Test Button')
          .accessibilityLevel('no')
      }.margin({ top: 20 })

      Text(this.text)
    }
    .width('100%')
    .height('100%')
    .onAccessibilityHoverTransparent((event: TouchEvent) => {
      if (event) {
        // Triggered on finger press.
        if (event.type === TouchType.HOVER_ENTER) {
          this.eventType = 'HOVER_ENTER';
        }
        // Triggered on touch move.
        if (event.type === TouchType.HOVER_MOVE) {
          this.eventType = 'HOVER_MOVE';
        }
        // Triggered on hand raise.
        if (event.type === TouchType.HOVER_EXIT) {
          this.eventType = 'HOVER_EXIT';
        }
        // Cancel the current event.
        if (event.type === TouchType.HOVER_CANCEL) {
          this.eventType = 'HOVER_CANCEL';
        }
        this.text = 'TouchType:' + this.eventType + '\nDistance between touch point and touch element:\nx: '
          + event.touches[0].x + '\n' + 'y: ' + event.touches[0].y + '\nComponent globalPos:('
          + event.target.area.globalPosition.x + ',' + event.target.area.globalPosition.y + ')\nwidth:'
          + event.target.area.width + '\nheight:' + event.target.area.height;
      }
    })
  }
}
```
